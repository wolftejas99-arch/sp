1. Difference Between SQL and NoSQL

SQL stands for Structured Query Language and is mainly used with relational databases. NoSQL means Not Only SQL and is used for non-relational database systems.
No.SQLNoSQL
1Relational databases.Generally non-relational databases.
2Data is stored in tables.Data may be stored as documents, key-value pairs, graphs, or columns.
3Uses a fixed or predefined schema.Usually has a flexible or dynamic schema.
4Data is organized into rows and columns.Documents or records can have different structures.
5Supports relationships between tables.Relationships are often handled through embedding or references.
6Uses SQL for querying data.Query language depends on the database.
7Commonly follows ACID transactions.Transaction and consistency models depend on the NoSQL system.
8Can use vertical and horizontal scaling depending on the system.Commonly designed for horizontal scaling.
9Suitable for highly structured data.Suitable for structured, semi-structured, or changing data.
10Examples: MySQL, PostgreSQL, Oracle, SQL Server.Examples: MongoDB, Cassandra, Redis, Neo4j.
11Normalization is commonly used.Denormalization is commonly used in many designs.
12Schema changes can require migrations.Schema changes are generally more flexible.
13Complex joins are supported.Traditional joins may be unavailable or handled differently.
14Common in banking, accounting and transaction-heavy systems.Common in large-scale and rapidly changing applications.
15Data consistency is often a major design priority.Systems may prioritize scalability, availability and performance depending on requirements.

SQL Example

SELECT * FROM students
WHERE age > 18;

NoSQL Example

{
  "id": 1,
  "name": "Rahul",
  "age": 20,
  "course": "CSE"
}

In short: SQL → structured, relational, tables, predefined schema. NoSQL → flexible, non-relational, documents/key-value/graph, flexible schema.

2. Working of API and Endpoints

API stands for Application Programming Interface. It allows different software applications to communicate with each other.
Frontend ↓ API Request ↓ Backend Server ↓ Database ↓ Backend Server ↓ API Response ↓ Frontend

What is an Endpoint?

An endpoint is a specific URL/address through which an API provides a particular resource or operation.

GET    /api/students
GET    /api/students/101
POST   /api/students
PUT    /api/students/101
DELETE /api/students/101

Common HTTP Methods

MethodPurpose
GETRetrieve data
POSTCreate new data
PUTUpdate existing data
PATCHPartially update data
DELETEDelete data

Working of an API

  1. Client sends a request.
  2. Request reaches the server.
  3. Backend identifies the endpoint.
  4. Backend performs business logic.
  5. Backend may communicate with the database.
  6. Database returns information.
  7. Server creates an API response.
  8. Client receives the response.

Example

GET /api/students/101
{
  "status": "success",
  "data": {
    "id": 101,
    "name": "Tejas",
    "course": "CSE"
  }
}

3. Spring Architecture and Spring Boot

What is Spring?

Spring Framework is a popular Java framework used for developing enterprise and web applications.

  • IoC — Inversion of Control
  • Dependency Injection
  • Spring MVC
  • Spring Data
  • Spring Security
  • Transaction management
  • AOP

Spring Application Architecture

Client ↓ Controller ↓ Service Layer ↓ Repository ↓ Database

Controller

Handles requests from the client.

@RestController
public class StudentController {

    @GetMapping("/students")
    public String getStudents() {
        return "Student List";
    }
}

Service

Contains business logic.

@Service
public class StudentService {

    public String getStudent() {
        return "Student Details";
    }
}

Repository

Communicates with the database.

@Repository
public interface StudentRepository
        extends JpaRepository<Student, Long> {
}

What is Spring Boot?

Spring Boot is built on top of Spring and simplifies the creation and running of Spring applications.

Major Features

  1. Auto Configuration
  2. Starter Dependencies
  3. Embedded Servers
  4. Production-ready features
  5. Less configuration
  6. Easy REST API development
  7. Spring Boot Actuator
  8. Easy database integration

Spring Boot Example

@SpringBootApplication
public class StudentApplication {

    public static void main(String[] args) {
        SpringApplication.run(StudentApplication.class, args);
    }
}

4. JUnit

JUnit is a Java testing framework used mainly for unit testing. Unit testing means testing a small individual part of an application, such as a method or class.

Advantages

  • Finds bugs early
  • Tests individual methods
  • Supports automated testing
  • Reduces manual testing
  • Helps maintain code quality
  • Useful during application development

Java Class

public class Calculator {

    public int add(int a, int b) {
        return a + b;
    }
}

JUnit Test

import static org.junit.jupiter.api.Assertions.assertEquals;
import org.junit.jupiter.api.Test;

class CalculatorTest {

    @Test
    void testAddition() {
        Calculator calculator = new Calculator();

        int result = calculator.add(10, 20);

        assertEquals(30, result);
    }
}

Important JUnit Annotations

AnnotationPurpose
@TestIdentifies a test method.
@BeforeEachRuns before each test.
@AfterEachRuns after each test.
@BeforeAllRuns once before all tests.
@AfterAllRuns once after all tests.
@DisabledDisables a test.

Common Assertions

assertThrows()

5. Spring Data JPA and ORM

What is ORM?

ORM stands for Object-Relational Mapping. It is a technique that maps application objects/classes to relational database data.
Java Class → Database Table Java Object → Database Row Java Field → Table Column

Example

public class Student {

    private Long id;
    private String name;
    private String course;
}

Corresponding database table:

STUDENT
-------------------------
id | name | course
-------------------------
1  | Ravi | CSE
2  | Rahul| ECE

What is JPA?

JPA stands for Java Persistence API. It is a Java specification/API used for managing relational database data using Java objects.

JPA is a specification; implementations include providers such as Hibernate.

What is Spring Data JPA?

Spring Data JPA is a Spring project that simplifies data access using JPA. It allows developers to create repository interfaces instead of writing large amounts of database access code manually.

Entity Example

@Entity
public class Student {

    @Id
    @GeneratedValue
    private Long id;

    private String name;
    private String course;
}

Repository Example

public interface StudentRepository
        extends JpaRepository<Student, Long> {
}

Spring Data JPA provides methods such as:

save()
findById()
findAll()
deleteById()
existsById()

How Spring Data JPA Works

Client ↓ Controller ↓ Service ↓ Spring Data JPA ↓ JPA ↓ Hibernate ↓ JDBC ↓ Database

One-Line Definitions for Exams

  • SQL: A language and relational database approach used to store and manage structured data in tables.
  • NoSQL: A database approach designed for non-relational data models and scalable applications.
  • API: An interface that allows different software applications to communicate.
  • Endpoint: A specific API address used to access a resource or operation.
  • Spring: A Java framework for developing modular and enterprise applications.
  • Spring Boot: A Spring-based framework that simplifies application development using features such as auto-configuration and starter dependencies.
  • JUnit: A Java framework used for automated testing of application code.
  • ORM: A technique for mapping objects in an application to relational database data.
  • JPA: A Java specification for persistence and ORM.
  • Spring Data JPA: A Spring abstraction that simplifies database access using JPA repositories.
